## 7. 卡点解除记录（2026-09-28）

**根因**：PMMS `add_model_source` 按 **.lib 段结构**枚举模型源；裸 `.model`（无 `.lib/.endl` 包装）时枚举为空 → 返回 code 8 "addModelSources returned empty"。这不是环境/license 问题，是**模型卡结构要求**。

**解法**（对照实验证据，账本原文）：
- 把甲卡包一层 `.lib tt / .endl tt`（`data/sim/jia_with_lib.inc`，jia.inc 原件未动），调用时**显式传** `lib_name="tt" + model_name="jiamod"` → 成功创建模型源 `jiamod_tt_N`（模拟器 Nano）；
- 对照：同一包装卡、同一会话，**缺省参数**调 add_model_source 仍 code 8（v2 账本 seq5/6，sha256 与旧失败逐字节相同）→ 显式 lib+model 是必要条件；同一卡，显式 lib+model 即成功（v2 seq7）→ 充分条件（在 license 已配置前提下；license 环境变量的单独贡献未做矩阵实验，标未验证）。
- 复跑验证（本人执行，16:20）：9/9 全过，set/get 往返 rdsmod 1→1.23 回读确认，计数 9=9。存档 `p2_smoke_v3.run2-output.txt`、`p2_v3_ledger.jsonl`。

**新发现（子任务2 前置问题）**：`list_params` 只列出模型卡上**显式声明**的参数（jia_with_lib.inc 只有 rdsmod=1，故只列一项）；v2 账本显示对未声明参数 voff 直接 set_param 报 **code 2 PARAM_INVALID**。全参数（voff/u0/…）写入路径待探——候选：set_param 带 `node_name`、或先在卡上声明、或 PMMS 另有"添加参数"语义（API §6.2 称"设置或添加"）。**此问题不解决，提取主链路无法调参，列为子任务2 开工第一件事。**

**附带事实**：模型源在工程中跨会话持久（v2 建的 `jiamod_tt_N` 与 v3 建的 `jiamod_tt_N_2` 同名叠加），清理用 `remove_model_source`。
