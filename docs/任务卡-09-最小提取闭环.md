# 任务卡 09：最小提取闭环 —— Agent 第一次"会调参"

- **阶段**：Phase 3 起步 —— 从"手动仿真"跨到"LLM 在环自动提取"
- **布置时间**：2026-09-18
- **前置条件**：任务卡 07（rdsmod 教训）+ 08 完成；甲器件 ground truth 已归档
- **状态**：✅ 已完成（首轮即收敛）

## 目标

跑通提取闭环的最小版本：给一个参数（voff）、一条曲线（线性区转移特性）、一个 LLM，
让 Agent 自己完成 **测量目标 → 仿真试算 → 对拍评估 → LLM 修正 → 再试算** 的完整循环。

## 架构（src/ 骨架第一批肉）

```
src/
├── tools/sim_tools.py    # ngspice 仿真工具：run_transfer(voff) → 曲线
├── eval/metrics.py       # nrmse（赛题 Card 评分同款口径）
├── agent/mini_loop.py    # LangGraph 状态机：simulate→evaluate→decide→propose(LLM)→simulate
└── pipeline/run_mini.py  # 入口：加载目标、设初始猜测、跑图、打印过程
```

图结构：

```
START → simulate → evaluate → decide ──收敛/超限──→ END
                            │
                            └─继续──→ propose(LLM) → simulate
```

- **simulate**：调 ngspice 用当前 voff 跑转移特性（网表/csv 留档可追溯）
- **evaluate**：算 NRMSE（试算 vs 目标）
- **decide（条件边）**：NRMSE<2% 或超 6 轮 → 收工；否则 → propose
- **propose**：把目标曲线和当前曲线的采样点摆给 LLM，它给下一个 voff + 理由

## 运行

```bash
conda activate gan-agent
python src/pipeline/run_mini.py
```

## ✅ 验收存档（2026-09-18 实测）

```
iter0: voff=-1.0000 V, NRMSE=20.54%
  LLM 提议 voff=-2.0 —— 仿真曲线相对实测整体右移约1V，需将voff左移1V使开启点对齐。
iter1: voff=-2.0000 V, NRMSE=0.00%
收敛 voff = -2.0000 V（真值 -2.0），收敛误差 0.0000 V
```

**一轮收敛**。原因：voff 是强可辨识参数——曲线平移量与 voff 误差一一对应，LLM 直接读出。
这验证了闭环架构成立，但也说明单参数太简单；多参数耦合（u0/voff/rd 联动）才是真考验。

## 踩坑记录

- **.env 不进 git**：本地仓库 clone 后 .env 不存在，OpenAI 客户端报 Missing credentials。
  已在本地补写（key 与服务器版相同）。**换机器记得带 .env**。
- **WSL 代理陷阱**：shell 里的 `127.0.0.1:7897` 代理跑在 Windows 主机上，而 WSL 的
  127.0.0.1 是 WSL 自己——变量指向虚空，SSL 握手必超时（`httpx.ConnectTimeout:
  handshake operation timed out`）。诊断口诀：**curl 直连通、走代理超时 = WSL/Windows
  回环混淆**。修复：mini_loop.py 加载 .env 后 `os.environ.pop` 摘掉代理变量走直连
  （DeepSeek 国内直连可达，curl 实测 0.16s）。
