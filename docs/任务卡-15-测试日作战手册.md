## T0 · 环境核对 + MCP 适配（0–1h）

**目标**：Agent 能通过组委会真 MCP 拿到第一条曲线。

动作：
1. 核对组委会 MCP 文档四项（卡14 §5）：transport（HTTP/SSE？地址？）、工具名、参数单位/取值范围、返回字段格式
2. 改适配层 **只改 `src/tools/mcp_sim.py`**：`SERVER_PATH` → 组委会地址；工具名/参数映射 → 按文档；**qa_loop.py 一行不动**
3. 单次调用冒烟：手搓一个默认参数调用，确认返回 JSON 能解析成数组

熔断：1h 内拿不到第一条曲线 → 上报组委会现场支持；同时把 mock server 的返回格式改成与文档一致继续调试，不空等。

## T1 · 冒烟 + 计数验证（1–2h）

**目标**：确认数据形态、点列数、单位，验证红线计数。

动作：
1. 用默认卡对器件 1 跑一次全网格仿真，存为 `day1_dev1_default.csv`——**这是全天所有 NRMSE 的对拍基准**
2. 记录单次仿真耗时 t_sim（决定全天仿真预算，见 §3）
3. 调 `get_call_count`（或等效机制）确认计数器工作

熔断：返回数据形态与练兵不一致（点数/扫描方向/符号约定）→ 先写解析适配，**别动 pipeline**；30 分钟搞不定上报。

## T2/T3 · 器件提取（每器件 7h，结构相同）

**目标**：QA 全过 + NRMSE 尽可能低 + 调用 ≥10 次。

动作（按序）：
1. **【0.5h】数据侦察**：默认卡曲线 vs 练兵基准形状对比——自热下垂？陷阱迹象？（知识表3 附表签名自检）
2. **【1h】转移特性起步**：sim_fn 指向转移形态，跑 qa_loop 闭环（voff+u0 起步）
3. **【3h】输出特性主战场**：847 点级网格闭环，双触发器自动扩族（rontr1 → rth0）
4. **【1.5h】外推验证**：未参与拟合的偏置点复测（卡10-bis 任务3 方法）；若反弹 >2×，记录风险并考虑扩空间
5. **【1h】收尾**：最优解模型卡导出 + 本器件调用计数核对

熔断与保底：
- **熔断 A**：单族精修 >100 次仿真仍 >5% → 检查数据形态归因（残差分段法，卡10-bis 任务1），别傻跑
- **熔断 B**：4h 时 NRMSE 仍 >3% → 接受当前最优 QA 过线解交卷（够用原则，卡13：0.60% 已是高分，3% 也能拿 0.97×QA）
- **熔断 C**：LLM API 挂了 → 换备用 key（Qwen/GLM）；全挂 → coarse 节点降级为 DEFAULTS 初值，纯优化器闭环（卡11 证明优化器+QA+expand 不依赖 LLM 质量）
- **熔断 D**：MCP 掉线 → 指数退避重试；连续 10 分钟不可用上报组委会并截图留证
- **保底红线**：任何时刻发现本器件调用 <10 次 → 立即用当前最优解补跑外推网格验证点（既攒调用又产证据，卡14 §4）
