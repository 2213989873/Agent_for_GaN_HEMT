### ③ 获取带 OSDI 的 ngspice

检查方法：ngspice 交互模式输入 `osdi`，显示用法说明 = 可用；"no such command" = 不可用。
（已实测确认：conda-forge 版 ngspice-41 无 OSDI——**版本号 ≥39 只是必要条件，编译时还必须开 `--enable-osdi`**）

**第 0 步：卸载 conda 版，避免 PATH 里有两个 ngspice 认错人**

```bash
conda remove -n gan-agent ngspice -y
hash -r
```

**方案 A（首选，免编译，解压即用）**：vyges-ngspice 预编译包（headless、`--enable-osdi`、linux-x86_64）：

```bash
mkdir -p ~/tools && cd ~/tools

# 直接下发布文件，不走 api.github.com（API 被服务器防火墙拦，curl 会无输出）
wget --timeout=30 -O vyges-ngspice.tar.gz "https://github.com/vyges-tools/vyges-ngspice/releases/download/v46/vyges-ngspice-46-gebdaf58ec76a-linux-x86_64.tar.gz"

# 文件应约 3.3 MB；若只有几 KB（404 页面）或下载失败，转方案 B
ls -la vyges-ngspice.tar.gz

tar xzf vyges-ngspice.tar.gz
source ~/tools/vyges-ngspice-*/env.sh
ngspice -v

# osdi 是交互命令，不能用管道喂（管道输入会被 ngspice 当成网表解析）
# 正确验法：直接敲 ngspice 进交互模式，在 ngspice 1 -> 提示符后输入 osdi，再输入 quit
ngspice
```

`osdi` 显示用法说明即成功。之后每次新开终端，先 `source ~/tools/vyges-ngspice-*/env.sh` 再用 ngspice。

⚠️ 若 `ngspice -v` 报 `GLIBC_2.38 not found` / `GLIBCXX_3.4.32 not found` = 预编译包在比本机新的系统上构建，**没救，直接放弃方案 A 转方案 B**；转之前**关掉当前终端重开一个**（清掉 env.sh 留下的 PATH/LD_LIBRARY_PATH，免得干扰编译）。已实测：本服务器（zhengjp@manager）正是这种情况。

**方案 B（备选，源码编译，约 5–10 分钟）**：SourceForge 发布包自编译（自带 configure，免 autogen；当前最新稳定版 47，2026-08-11 发布）：

```bash
conda activate gan-agent
conda install -c conda-forge gcc gxx make automake autoconf libtool bison flex readline -y
cd ~/tools

# 依次尝试 47/46/45/44，哪个能下就用哪个
for v in 47 46 45 44; do
  wget --timeout=30 -O ngspice-$v.tar.gz "https://downloads.sourceforge.net/project/ngspice/ng-spice-rework/$v/ngspice-$v.tar.gz" \
    && tar tzf ngspice-$v.tar.gz >/dev/null 2>&1 && break
  rm -f ngspice-$v.tar.gz
done

tar xzf ngspice-*.tar.gz && cd ngspice-*/
mkdir -p release && cd release
../configure --enable-osdi --enable-openmp --without-x --without-readline --prefix=$HOME/local CFLAGS="-O2 -std=gnu11"

# 关键检查点：configure 成功的唯一标志是生成了 Makefile，没有它后面全是空转
ls -la Makefile

make -j$(nproc) && make install

# 把 $HOME/local/bin 永久加进 PATH
echo 'export PATH="$HOME/local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
hash -r
which ngspice
ngspice -v

# osdi 是交互命令，不能用管道喂（管道输入会被 ngspice 当成网表解析）
# 正确验法：直接敲 ngspice 进交互模式，在 ngspice 1 -> 提示符后输入 osdi，再输入 quit
ngspice
```

`which ngspice` 应显示 `/home/zhengjp/local/bin/ngspice`，交互模式里 `osdi` 显示用法说明即成功。

✅ **已完成记录（2026-09-16，zhengjp@manager）**：ngspice-47 按方案 B 编译安装成功（`--enable-osdi --without-readline`），configure 日志含 `OSDI features included`。

⚠️ **已踩坑记录**：
1. github.com/ngspice/ngspice 是 2015 年停更的僵尸镜像（clone 下来是 rev 26，无 OSDI），勿用
2. conda-forge 预编译版（ngspice-41）无 OSDI——版本新 ≠ 开了 OSDI
3. api.github.com 被服务器防火墙拦截（curl 无输出），下载要走 releases/download 直链
4. `sourceforge.net/projects/.../files/...` 网页路径直接 wget 会 404，要用 `downloads.sourceforge.net/project/...` 形式
5. 源码编译遇 `'bool' cannot be defined via 'typedef'` = conda 新版 GCC 默认 C23，configure 加 `CFLAGS="-O2 -std=gnu11"` 强制 C11 即可
6. `libtinfo.so.6: no version information available` 警告和 `no graphics interface` 报错都无害（服务器无显示器），批处理 `-b` 模式不受影响
7. vyges 预编译包报 `GLIBC_2.38 not found` / `GLIBCXX_3.4.32 not found` = 包在比本机新的系统上构建，预编译二进制对老服务器无解，转方案 B 源码编译（编译产物链接本机库，天然免疫此类问题）
8. configure 报 `Couldn't find readline libraries`（头文件明明 yes）= conda 版 readline 的链接测试 configure 处理不好；readline 只管交互模式的行编辑，批处理用不到，加 `--without-readline` 直接关掉
9. `echo -e "osdi\nquit" | ngspice` 报 `could not find a valid modelname` / `empty netlist` = **管道喂 stdin 时 ngspice 把输入当电路网表解析**，不执行交互命令；osdi 这类命令必须开真交互模式（直接敲 `ngspice` 进提示符）手动输入

版本检查：`ngspice -v` 第一行应显示 **revision ≥ 39**，且交互模式 `osdi` 命令有响应。

### ④ 装 OpenVAF

**已核实（2026-09-16，GitHub API 返回）**：原版 pascalkuthe/OpenVAF 的 GitHub release **资产为空**（2023 年发布时未传二进制，semimod 页面成死链）；维护方已转向 **OpenVAF-Reloaded**，最新版 **v24.0.2mob**（2026-08-25，OSDI 0.4 接口，ngspice ≥44 支持，本机 ngspice-47 ✅）。

```bash
cd ~/tools
wget --timeout=60 -O openvaf-r.tar.gz "https://github.com/OpenVAF/OpenVAF-Reloaded/releases/download/v24.0.2mob/openvaf-r-v24.0.2mob-linux-x86_64.tar.gz"

# 应约 26 MB（26,226,644 字节）；明显偏小就是又 404 了，贴给 Kimi
ls -la openvaf-r.tar.gz

# 先看包里结构，再解压
tar tzf openvaf-r.tar.gz | head
tar xzf openvaf-r.tar.gz

# 已实测包内结构：openvaf-r-v24.0.2mob-linux-x86_64/bin/openvaf-r（可执行文件在第 3 层）
cp openvaf-r-v24.0.2mob-linux-x86_64/bin/openvaf-r $HOME/local/bin/
chmod +x $HOME/local/bin/openvaf-r

# 建个统一名字的软链接，后续命令和竞赛文档习惯写法一致
ln -sf $HOME/local/bin/openvaf-r $HOME/local/bin/openvaf
hash -r
openvaf --help | head -5
```

`openvaf --help` 正常输出即成功。⚠️ 预案：OpenVAF 产出 .osdi 时需调用系统链接器（`which ld` 确认；没有就 `conda install -c conda-forge binutils -y`）；若 ⑤ 报错提到 linker / ld / cc，把报错贴给 Kimi

❌ **openvaf-r 路线已实测判死（2026-09-16）**：v24.0.2mob 要求 **GLIBC_2.39**（GitHub Actions 新系统构建），本机 glibc 给不了；且 tar 包仅含 `bin/openvaf-r`，需另装 libLLVM18（已装，留着无害）。**本机不可用，改走下面的 2023 独立版。**

✅ **OpenVAF 正式路线（2023 独立构建版，静态链接自带 LLVM，老 glibc 友好）**：OpenVAF-Reloaded 维护者（SPICE OPUS 小组）官网 spiceopus.si 托管的 devel 包，53 MB，2023-06-05 构建：

```bash
cd ~/tools
wget --timeout=120 -O openvaf-devel.tar.gz "http://www.spiceopus.si/download/openvaf_devel-x86_64-unknown-linux-gnu.tar.gz"

# 应约 53 MB
ls -la openvaf-devel.tar.gz

# 看结构再解压
tar tzf openvaf-devel.tar.gz | head -5
tar xzf openvaf-devel.tar.gz

# 精确定位名为 openvaf 的可执行文件（排除 openvaf-r 和压缩包）
find . -maxdepth 3 -type f -name "openvaf" ! -name "*.tar.gz"

# 装为 openvaf-devel，并把 openvaf 软链接改指到它（openvaf-r 在本机是死的不删也无害）
cp $(find . -maxdepth 3 -type f -name "openvaf" ! -name "*.tar.gz" | head -1) $HOME/local/bin/openvaf-devel
chmod +x $HOME/local/bin/openvaf-devel
ln -sf $HOME/local/bin/openvaf-devel $HOME/local/bin/openvaf
hash -r
openvaf --help | head -5
```

✅ **已完成（2026-09-16）**：spiceopus 2023 独立版（53 MB 静态）在本机正常运行，`openvaf --help` 输出用法。注意：23.2.0 起 OpenVAF 去掉了内置 LLD，**编译 .osdi 时需要系统 `ld`**（`which ld` 确认；没有就 `conda install -c conda-forge binutils -y`）。

✅ **已踩坑并解决（2026-09-16）**：`error while loading shared libraries: libLLVM.so.18.1` = openvaf-r 动态链接 LLVM 18 而 tar 包不含库（已实测包内仅 `bin/openvaf-r`）。修法：

```bash
conda install -c conda-forge libllvm18 -y
ls $CONDA_PREFIX/lib/libLLVM* | head
which ld || conda install -c conda-forge binutils -y
export LD_LIBRARY_PATH=$CONDA_PREFIX/lib:$LD_LIBRARY_PATH
openvaf --help | head -5

# 能跑后写进 .bashrc 永久生效（用绝对路径，不要用 $CONDA_PREFIX——.bashrc 执行时它指向 base）
echo 'export LD_LIBRARY_PATH=/data/zhengjp/anaconda3/envs/gan-agent/lib:$LD_LIBRARY_PATH' >> ~/.bashrc
```

⚠️ conda 安装必须**等它跑完**：`CondaError: KeyboardInterrupt`（Ctrl+C 中断）= 什么都没装上，后续报错原样重现。repodata 索引（几百 MB）下载几分钟是正常的，别中断。若 5 分钟以上不动，换清华 TUNA 镜像单飞：

```bash
conda install -c https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge libllvm18 -y
```
