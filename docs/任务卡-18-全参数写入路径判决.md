## 由此确立的真链路纪律（写入 agent 设计）

1. **可调参数集合 = 模型卡上声明的参数**。提取流程每轮扩参数族时：重新渲染卡（新增参数带初值写进 .model 行）→ `load_model` → `add_model_source`（显式 lib/model）→ 旧源用 `remove_model_source` 清理（模型源在工程中跨会话持久，任务卡17 §7 已证）。
2. **optimize 的 param_string 只写参数名**（不带模型源名），且**必须照抄 list_params 的名字**——guide 原文："参数名写错仍会被服务端静默跳过（只表现为'优化没效果'）"。→ QA 新增规则：优化前 param_string ∩ list_params 校验，有差集即告警。
3. `model_source_name` 来源优先级（guide 原文）：用户/上下文 → 本次 view 的 source_string 第二段 → list_model_sources 查询。
4. param_string 支持 `prefix.`/`end.`/`device(...)` 批量匹配（guide §1/§5），120 参数分组优化时可用来按族选取——待子任务3 实测。
