## 0. 目标与总策略

**目标：不是完赛，是高分。** 再明确一次得分公式：

- 单器件得分 = QA 通过率 × (1 − 归一化曲线误差)
- 总分 = 0.7 × 两器件平均 + 0.3 × 两器件最低分

由此定下三条总策略，全程不动摇：

1. **QA 全过 > 曲线极致贴合**。QA 是乘性因子，物理检查挂几项，拟合再好也白费。
2. **不偏科**。min 项占 30%，所有流程按"两个性格不同的器件都能跑"来设计，不为单个器件定制捷径。
3. **稳健 > 聪明**。LLM 只做"有限选项中的决策"，数值计算、流程控制、拟合调用全部用确定性代码。这是单人作战防翻车的根本原则。

## 1. 终点蓝图：我们要建成什么

一个基于 **LangGraph 状态机** 的 Agent 系统，节点如下（评委要看图结构，状态机天然可审计）：

```
load_data → analyze_data → init_params → extract_dc → extract_cv → extract_rf
    → physics_qa →（通过）→ finalize_card → write_logs
                 ↘（失败）→ retune_decide → 回到对应 extract_* 节点
```

| 节点 | 类型 | 职责 |
|---|---|---|
| load_data | 确定性代码 | 加载 I-V / C-V / 脉冲 I-V / S 参数数据，完整性检查 |
| analyze_data | LLM | 看曲线特征，判断器件特性（自热强不强、有无陷阱迹象） |
| init_params | 规则+LLM | 给 ~120 个参数设初值 |
| extract_dc / extract_cv / extract_rf | 确定性调 MCP | 分模块拟合：先直流 I-V，再 C-V，再脉冲/S 参数（陷阱、自热、寄生） |
| physics_qa | 确定性代码 | 单调性、对称性、kink、参数物理范围检查 |
| retune_decide | LLM | QA 失败时，根据"失败-修复映射表"选修复策略，条件边回退 |
| finalize_card | 确定性代码 | 生成 ASM-HEMT 模型卡 + 官方 Schema 校验 |
| write_logs | 确定性代码 | 汇总 MCP 调用记录、LLM 统计、决策摘要（提交物） |

横切能力（贯穿所有节点）：checkpoint 状态持久化、指数退避重试、token / 时间预算监控、全程日志。

**反作弊合规是天然满足的**（正常流程 MCP 调用远超 10 次、必用国产大模型），但日志必须完整可自证。

## 2. 阶段计划（12 周；官方日程确认后整体平移）

### Phase 0 · 立项准备 ｜ 9/14 – 9/20（本周）

- [ ] 确认官方日程：报名状态、**测试日日期**、赛题 Q&A 文件、MCP 文档发放时间 → 填回本文档
- [ ] 环境：Python 3.10+、Git、VS Code；Windows 机器建议装 WSL2 + Ubuntu 22.04（官方推荐环境）
- [ ] 申请大模型 API：DeepSeek 做主开发（便宜），通义千问或智谱 GLM 做备用（决赛允许多模型混用）
- [ ] 初始化 Git 仓库与目录结构（我给模板）
- [ ] 建学习笔记本（markdown 即可，放仓库 `docs/`）

**产出**：环境可用 + 仓库初始化 + 官方日程表

### Phase 1 · 三线打基础 ｜ 9/21 – 10/11（第 1–3 周）

**线 A · Agent 工程（约 60% 时间）**
- LangGraph 官方快速入门 + 状态机教程，手写 2 个 demo
- MCP 协议：用 FastMCP 写一个最小 server + client，会列工具、发调用、读结果
- DeepSeek function calling 练熟

**线 B · 器件最小知识（约 25%，单人版重点补强）**
- 晶体管基础：输出特性、转移特性、阈值电压、线性区 / 饱和区
- 四类数据各测什么：DC I-V（直流特性）、C-V（电容电荷）、脉冲 I-V（陷阱与自热）、S 参数（射频小信号）
- ASM-HEMT 参数分组地图：极化 / 自热 / 陷阱 / 场板四大物理效应对应哪些参数组
- 读 ASM-HEMT 标准论文的参数提取章节（我给导读，只读需要的 20%）

**线 C · 数据能力（约 15%）**
- pandas + matplotlib：读数据、画曲线、算 RMSE

**Checkpoint（全过才算完成）**：
1. 独立写出"LLM + 3 个自定义工具"的 LangGraph demo
2. 看一张 I-V 曲线能指出阈值电压、线性区、饱和区、自热回滞
3. 能把上面两条讲给 Kimi 听（我抽查）

### Phase 2 · 最小闭环（先不用 AI）｜ 10/12 – 11/1（第 4–6 周）

- 自造训练数据：ngspice + 开源 ASM-HEMT Verilog-A 模型，合成 2 个"性格不同"的虚拟器件——器件甲（标准特性）、器件乙（强自热 / 强陷阱），各生成四类曲线
  - **备选 B**：ngspice 编译 VA 模型若卡住超过 1 周，改用公开数据先跑通，回头再补
- 用 FastMCP 自建 mock Modeling Server，接口对齐组委会文档（load / fit / qa / export）
- 手写确定性 pipeline（零 LLM）走通全流程
- 组委会真环境开放后第一时间切换验证

**Checkpoint**：手动 pipeline 对器件甲提取成功，自评隐藏点 RMSE < 5%
**产出**：pipeline 代码 + 合成数据集 + mock/真环境接口适配层

### Phase 3 · Agent 化（核心阶段）｜ 11/2 – 11/29（第 7–10 周）

- 按蓝图实现完整 LangGraph 图
- **三张专家知识表**（我带你逐条写，这是本赛题的灵魂）：
  1. 提参顺序表——每个模块先提哪些参数、锁定哪些
  2. 参数-曲线段映射表——哪段曲线不对，定位到哪几个参数
  3. QA 失败-修复动作映射表——每种 QA 失败对应什么 retune 动作
- 健壮性工程：重试、限流退避、超时、checkpoint、预算监控
- 自建评分脚本（模拟官方公式），双器件交叉测试
- 至少完成 3 轮"失败 → 分析 → 改进"迭代

**Checkpoint**：两个合成器件全自动提取成功，自建评分两器件均 > 0.7
**产出**：Agent v1.0 + 评测报告

### Phase 4 · 冲刺 ｜ 11/30 – 赛前（第 11–12 周）

- 2 次 24 小时全真模拟（掐表 + 断网演练 + API 限流演练）
- 提交包：仓库规范、架构图、依赖声明、模型卡 Schema 自动校验器
- 应急预案手册 + 红线自查清单
- 测试日作战计划：时间轴、值班与睡眠节奏、监控报警
